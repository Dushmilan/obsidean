# FastAPI Fundamentals & First Steps

FastAPI is a modern Python web framework built on **type hints**. You declare your request and response shapes with Python types, and FastAPI gives you **validation**, **serialization**, **OpenAPI docs** (`/docs`), and **async support** for free. It's the standard choice for Python APIs that need speed, safety, and self-documentation.

**The Intuition:** Most frameworks make you write validation, parsing, and docs by hand — three separate chores that drift apart. FastAPI flips it: *one* type declaration (`user: User`) is simultaneously the parser, the validator, the serializer, and the doc generator. You write the types once; FastAPI derives everything else.

## The minimal app

```python
from fastapi import FastAPI

app = FastAPI()                      # the application object


@app.get("/")                        # decorator: method + path
def read_root():
    return {"message": "Hello World"}   # dict → JSON automatically


@app.get("/items/{item_id}")         # path parameter
def read_item(item_id: int):         # type hint = validation + conversion
    return {"item_id": item_id}
```

```bash
uvicorn main:app --reload            # run: file:variable, --reload for dev
# Docs at http://localhost:8000/docs (Swagger UI)
# Also: /redoc, and the OpenAPI JSON at /openapi.json
```

**What you get for free:**
- `GET /items/abc` → **422** validation error (can't convert `abc` to `int`)
- `GET /items/3` → `{"item_id": 3}`
- Interactive `/docs` — try endpoints, see schemas, autogenerated from your types

## Type hints = validation

```python
from typing import Optional

@app.get("/search")
def search(
    q: str,                          # required query param
    limit: int = 10,                 # optional, defaults to 10
    published: bool = False,         # /search?published=true
    tags: Optional[list[str]] = None,  # /search?tags=a&tags=b
):
    return {"q": q, "limit": limit, "published": published, "tags": tags}
```

**The contract:** every parameter's *type* is its validation rule. `int` rejects non-integers, `bool` understands `true/yes/1`, `list[str]` collects repeated params. Wrong types → automatic 422 with a structured error body. No manual `if not isinstance(...)`.

## async vs def endpoints

```python
import asyncio

# def — runs in a threadpool (for blocking work: file I/O, CPU, sync DB drivers):
@app.get("/def")
def blocking_work():
    return compute_expensive()            # runs off the event loop

# async def — runs on the event loop (for awaitable I/O: aiohttp, asyncpg, httpx):
@app.get("/async")
async def non_blocking():
    data = await asyncio.sleep(0.1)       # yields the loop while waiting
    return {"data": data}
```

**The rule:** if the endpoint does *any* blocking work (sync DB driver, `requests`, heavy compute), use `def` — FastAPI runs it in a threadpool so the event loop stays free. If it's all `await`-able, use `async def`. Mixing a blocking call inside `async def` blocks the whole loop.

## Response models — the return contract

```python
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float
    in_stock: bool = True                # default → optional in requests

class ItemOut(BaseModel):
    id: int
    name: str
    price: float


@app.post("/items", response_model=ItemOut, status_code=201)
def create_item(item: Item):             # request body = validated Item
    stored = save_to_db(item)
    return stored                        # filtered/serialized to ItemOut
```

**Why a separate response model:** it's a filter and a contract. Even if your internal dict has extra fields (or a password!), only `ItemOut`'s fields are sent. This is how you never leak internal data by accident.

## The router — organizing endpoints

```python
# app/routers/items.py
from fastapi import APIRouter

router = APIRouter(prefix="/items", tags=["items"])

@router.get("/")
def list_items(): ...

@router.get("/{item_id}")
def get_item(item_id: int): ...

# app/main.py
from app.routers import items

app.include_router(items.router)         # mounted at /items
```

**The intuition:** `APIRouter` is a mini-app — paths, tags, and dependencies can be grouped (like Express `Router`). `prefix="/items"` means routes inside are `/items`, `/items/{id}`. Tags group them in the docs.

---

**Setup:** An endpoint that converts a query param and returns it, handling a required and optional value.

**Solution:**
```python
@app.get("/price")
def price(
    amount: float,
    currency: str = "USD",
    discount: float = 0.0,
):
    final = amount * (1 - discount)
    return {"amount": final, "currency": currency}

# /price?amount=100&currency=EUR&discount=0.1 → {"amount": 90.0, "currency": "EUR"}
# /price?amount=abc → 422 (not a float)
```

**Key insight:** types do the work — `float` converts and rejects garbage, defaults make params optional, and the docs show all three params automatically. Zero manual parsing.

---

**Setup:** A POST endpoint that takes a JSON body, validates it, and returns a subset.

**Solution:**
```python
class UserIn(BaseModel):
    email: str
    password: str
    age: int | None = None

class UserOut(BaseModel):
    email: str
    age: int | None = None


@app.post("/users", response_model=UserOut, status_code=201)
def create_user(user: UserIn):
    # user.password exists here, but NEVER in the response
    stored = save_user(user)            # whatever internal shape
    return stored                       # serialized through UserOut only
```

**Key insight:** `UserIn` and `UserOut` are separate contracts. The password is required *in*, and structurally impossible *out* — the response model strips it even if `save_user` returns it. This separation is the default safe pattern.

---

**Setup:** Why does a bad `int` query param return 422 instead of crashing?

**Solution:** FastAPI validates every parameter against its type *before* the function runs. `item_id: int` with `abc` fails conversion → a 422 error is returned with a structured body listing the field and the error. Your function body never executes — so it can't crash on bad input. You get 422s *instead of* 500s.

**Key insight:** validation happens at the *boundary*, automatically. The framework rejects invalid input with a clear, documented error; your code only ever sees valid data. This is the core value proposition of type-hint-driven frameworks.

## Practice (try before peeking)

1. What three things does one type hint on a parameter give you?
2. `def` vs `async def` — when would you pick each?
3. Why a separate response model instead of returning the internal object directly?

<details><summary>Answers</summary>

1. Validation (wrong types → 422), conversion/parsing (string → int/bool/list), and documentation (the schema appears in `/docs`). One declaration, three jobs.
2. `async def` when the endpoint is all awaitable I/O — it runs on the event loop. `def` when there's blocking work (sync DB driver, CPU, file I/O) — FastAPI runs it in a threadpool so it doesn't block the loop. Wrong choice: blocking call inside `async def` stalls everything.
3. To enforce the *public contract*: response models filter what's sent (no internal fields, no passwords), make the API shape explicit, and document it. Returning raw objects risks leaking internals and coupling your API shape to your storage shape.

</details>

---

**Common traps:**
- Blocking calls inside `async def` endpoints — freezes the event loop
- Returning internal objects with sensitive fields — always use a response model
- Forgetting `status_code=201` on creates (defaults to 200)
- Not putting endpoints in routers — one giant `main.py` with everything
- Catching validation errors manually instead of letting FastAPI do it
